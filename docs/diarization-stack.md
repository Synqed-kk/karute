## 1. How Plaud actually does it (2026-corrected)

HOW PLAUD ACTUALLY DOES IT (2026-verified, corrects the April spike doc): Layer 1 hardware is real but modest — Note Pro = 4 MEMS mics + 1 'VPU' (5m pickup); a teardown shows the VPU is a bone-conduction mic for call-mode, NOT a noise-isolation processor. Layer 2 'AI beamforming' is marketing that Plaud itself has quietly softened — the current Note Pro page dropped the lock-on/noise-isolation claims, no teardown verifies any beamforming DSP, and reviews + Plaud's own support docs admit accuracy degrades and speakers merge in loud/overlapping environments. The directional lock does NOT solve bystander rejection in a multi-bed salon. Layer 3 is now answered: Azure-hosted Whisper large-v3 (likely fine-tuned), with diarization built in-house/undisclosed — retire the Deepgram/AssemblyAI/NeMo candidate list for Plaud. Layer 4 confirmed: user-selectable GPT/Claude/Gemini summarization. THE BIG NEW FACT (shipped Feb 2026): 'Auto speaker labeling' — the owner enrolls a 30-second voice profile in settings; everyone else is learned IMPLICITLY from labels you assign once in a transcript, then auto-applied to the same voice in future recordings; profiles are user-deletable (APPI-compatible). Net: Plaud's speaker isolation is ~80% software (diarization + enrollment + label-learning), ~20% hardware. That software pattern — explicit staff enrollment + implicit customer learning from corrections — is exactly the blueprint Karute needs, and it requires zero hardware. Bonus: Plaud now sells a Developer Platform (device SDK + transcription API, targeting vertical CRMs) — a viable Phase-2 capture vendor for us, not just a competitor.

## 2. Karute today — the honest audit

HONEST CURRENT STATE (audited against origin/main bebcda9, 2026-06-08): Diarization is ON — the transcribe route defaults speaker_diarization to true and Deepgram nova-3 ja returns word-level speaker indices + speaker-turn paragraphs (src/lib/deepgram.ts, src/app/api/ai/transcribe/route.ts). Then we throw it away: src/lib/ai-pipeline.ts reads ONLY transcribeData.transcript; words/paragraphs are never consumed, never persisted (karute_records.transcript is a flat string). There is NO speaker→role mapping anywhere — no first-speaker heuristic, no speaker map, no embeddings. Extraction/summary prompts (src/lib/prompts.ts) receive flat text with zero speaker awareness, so in a noisy salon TODAY the neighboring bed's customer describing her symptoms can be extracted into THIS customer's karte — the model literally cannot tell whose words are whose. Voice enrollment is a UI-only stub (VoiceEnrollmentDialog.tsx: fake timer, audio discarded, no backend route, no DB columns). LiveTranscriptCard is hard-coded empty. The noise_suppression setting saves to org_settings but is never applied to getUserMedia (recorder uses bare {audio:true}). Signed-URL TTL is 1 hour (comment says 10 min). Bottom line: we pay an extra $0.002/min for diarization and discard 100% of it; in a noisy salon the product behaves as if diarization were off.

## 3. The staged stack

- STAGE 0 — Stop discarding what we already pay for (effort: 2-4 dev-days; cost: $0 added — diarization already on at +$0.002/min). Pass Deepgram's words/paragraphs through ai-pipeline.ts, persist the spike's DiarizedTranscript contract (speakers[], segments[] with confidence, fallbackText) instead of a flat string, apply H1 'first speaker = staff' (~85% accurate) plus prompt-side role attribution (staff talks technique/instructions, customer talks symptoms — yes, this heuristic works as a tiebreaker, give the LLM both signals), and add confidence gating: segment confidence <0.45 → role 'unknown' shown for staff verification, overall <0.55 → plain transcript + banner. Update prompts.ts to extract ONLY from staff/customer-attributed speech and explicitly ignore unknown/bystander segments. FIXES: the wrong-customer-extraction failure mode, immediately, with zero new vendors.

- STAGE 1 — Staff voice enrollment, the Plaud pattern (effort: 1-2 weeks; cost: +~$0.15/hr ≈ pyannoteAI identification €0.015/hr + Precision-2 €0.112/hr, voiceprints €0.035 one-time per staff; 150-hr free trial). Keep Deepgram nova-3 ja for words; run pyannoteAI voiceprint identification on the same audio in parallel, merge by timestamps. Staff = named via enrolled voiceprint; customer = the non-staff speaker with most turn-taking adjacency to staff; residual far-field/short segments = bystanders, rejected. Ship the spike's APPI backend WITH it: staff.voice_embedding pgvector + voice_enrolled_at, audit log, one-click revocation, 30-day purge, raw audio discarded after embedding — the consent UI already exists. Before committing, benchmark two alternates on the same recordings: Speechmatics (only all-in-one ASR+diarization+enrolled-ID, batch AND realtime, ~$0.30/hr) and OpenAI gpt-4o-transcribe-diarize ($0.36/hr, known_speaker_references, but chunk-drift reports). FIXES: deterministic staff identification, named transcript labels, real bystander rejection. This is the layer that solves Liam's stated problem.

- STAGE 2 — Phone-side capture hygiene (effort: days; cost: $0). Apply the already-saved org settings to getUserMedia constraints (noiseSuppression, echoCancellation), adopt iOS 26 Voice Isolation mic mode for recording sessions (now available to recording apps, iPhone XR+), Android via Picovoice Koala if needed. Hard truth: this suppresses BGM/dryers/non-voice noise only — NO phone API rejects other VOICES, and Apple exposes no beamforming to third parties. Do NOT use Krisp background-voice-cancellation (keeps only the loudest speaker — would suppress the customer). FIXES: noise floor and Deepgram/pyannote accuracy; bystander voices stay a server-side problem by physics.

- STAGE 3 — Optional hardware, at-volume only (effort: integration project; cost: $179+/device + per-usage API). If real-salon benchmarks after Stages 0-2 still show unacceptable bystander leakage, evaluate a dedicated mic: Plaud Note Pro / NotePin S via the new Plaud Developer Platform (BLE/WiFi device SDK + transcription API, explicitly sold to vertical CRMs), or simply a positioned dedicated iPhone per bed. Go in skeptical — Plaud's own beamforming claims are unverified and their support docs admit speaker-merging in noise. Hardware buys you mic placement and pickup range, not magic isolation. FIXES: capture quality at distance; marginal gain on bystander rejection.

## 5. Risks (the decision mechanism is the benchmark set, not vendor claims)

- JA diarization accuracy is unproven territory: Deepgram publishes no ja-specific DER, every vendor's headline numbers are English-weighted, and 整体 vocabulary is jargon-heavy. The benchmark set is not optional — it is the decision mechanism. Budget for the possibility that nova-3 ja diarization underperforms and AssemblyAI (explicit ja diarization + 2025 noisy-environment upgrades) or ElevenLabs Scribe (best published ja WER) wins on words.
- Bystander leakage survives perfect tooling: overlapping speech and similar voices merge speakers — Plaud's own docs admit it, and INTERSPEECH 2026 evidence shows everything degrades with speaker count + overlap. Mitigation is product design, not provider choice: low-confidence segments surface as 要確認 for staff review, never silently included or dropped. Staff actually reviewing is an ops behavior we must drive.
- Worst failure mode is misattribution, not omission: extracting a neighboring customer's symptoms into this customer's karte is a trust-destroying, medical-adjacent error. All thresholds must bias toward 'unknown' over guessing; extraction prompts must refuse unattributed clinical claims.
- APPI biometric exposure: voice embeddings are biometric PII. Opt-in consent, per-staff revocation, 30-day purge, and audit logging must ship in the same release as enrollment — today the repo has consent copy with zero backend, which is the dangerous half-built state. Customer voices stay anonymous (never enrolled) by design.
- Recording-disclosure gap: disclosure_mode (A/B/C) is stored but drives nothing at runtime — silent Mode A recording without the spike's privacy-policy gating and discreet-indicator UX is live legal/reputational exposure in stores today, independent of the speaker work.
- Vendor fragility on the enrollment layer: Azure Speaker Recognition was retired Sept 2025 with the whole market pointing at it; pyannoteAI is a small company; gpt-4o-transcribe-diarize already has a 2027 retirement date. Keep a thin provider abstraction and retain raw audio per retention policy so historical sessions can be re-processed if we must swap.
- Physics: no phone software does voice-vs-voice directional rejection. If salon layouts put beds <2m apart, mic placement SOP (phone between staff and customer, facing away from the neighboring bed) matters as much as any model — and the spike's 'hardware Phase 2' split stands confirmed.
